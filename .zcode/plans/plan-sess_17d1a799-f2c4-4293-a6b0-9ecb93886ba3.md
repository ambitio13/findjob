# Subtask 3: Job/Application Upsert From Browser JD

## Goal
Turn the browser-read JD dict (from `UserscriptBossPage.read_current_jd()`) into durable product data — a `JobPosting` + `ApplicationRecord` — with provenance, deduped by `platform=boss + page_url_hash`.

## Design Decisions

### Provenance storage: `jd_normalized` JSON (not new columns)
The `JobPosting` model has no `source_kind`/`page_url_hash`/`read_at`/`agent_run_id` columns. Rather than adding a migration for every provenance field, we store provenance inside the existing `jd_normalized` JSON column under a `_source` key — consistent with the existing `_extraction` provenance pattern in `jd_parse_service.py` (line 316). This avoids a migration and matches the codebase convention.

```python
jd_normalized = {
    "_source": {
        "source_kind": "boss_userscript_read_jd",
        "page_url_hash": "sha256:abcdef12",
        "read_at": "2026-08-03T...",
        "agent_run_id": "run_...",
    },
    "fields": {  # structured JD fields from read_jd
        "title": "...", "company": "...", "location": "...",
        "salary": "...", "experience": "...", "education": "...",
        "skills": [...], "description": "...",
    },
}
```

### Dedup strategy: `platform=boss` + `external_id = page_url_hash`
The `JobPosting` model already has `external_id` (String 128, nullable). We use it to store the `page_url_hash` for BOSS-read jobs. The dedup query finds an existing job with `platform="boss"` + `external_id=page_url_hash` + `user_id=current_user.id`. This reuses an existing column — no migration needed.

### Service: `BOSSRecommendedJobService` (new file)
A new service module `backend/app/services/boss_recommended_job_service.py` owns the inspect flow orchestration. For Subtask 3, it implements:
- `inspect_current_job(db, current_user, *, jd_dict, agent_run_id) -> InspectResult` — the core upsert method.

### API: `POST /boss/recommended-jobs/current/inspect` (new endpoint)
A new router module `backend/app/api/v1/boss_recommended_jobs.py`. The endpoint:
1. Receives a request body with `resume_version_id` (optional, for attaching an application).
2. Reads the JD from the browser via `UserscriptBossPage.read_current_jd()`.
3. Calls `BOSSRecommendedJobService.inspect_current_job()` to upsert Job + Application.
4. Returns the job + application + inspect status.

Since `read_current_jd()` is async (goes through the userscript channel), the endpoint is `async def`. The endpoint creates an `AgentRun` for provenance before reading the JD.

## Files to Create/Modify

### 1. NEW: `backend/app/services/boss_recommended_job_service.py`
Core service with:
- `WORKFLOW_TYPE = "boss_recommended_job_inspect"`
- `JD_TOO_SPARSE` minimum fields check (title + description required)
- `upsert_job_from_browser_jd(db, *, user_id, jd_dict, agent_run_id) -> tuple[JobPosting, bool]` — dedup by `platform=boss` + `external_id=page_url_hash`; update existing or create new; store provenance in `jd_normalized._source`; return `(job, is_new)`.
- `inspect_current_job(db, current_user, *, jd_dict, agent_run_id, resume_version_id=None) -> InspectResult` — calls upsert_job, then creates/reuses an ApplicationRecord via the existing `application_repo.find_duplicate` pattern.

Add to `job_repo.py`:
- `find_by_platform_and_external_id(db, *, user_id, platform, external_id) -> JobPosting | None` — dedup query.
- Reuse existing `create()` and `update()` for insert/update.

### 3. NEW: `backend/app/schemas/boss_recommended_job.py`
Pydantic models:

### 4. NEW: `backend/app/api/v1/boss_recommended_jobs.py`
Router with `POST /boss/recommended-jobs/current/inspect`:
- Creates an AgentRun (workflow_type=`boss_recommended_job_inspect`, status=`running`).
- Gets the userscript channel singleton.
- Creates a `UserscriptBossPage` and calls `read_current_jd()`.
- If JD is None → `read_failed`.
- If JD too sparse (no title or no description) → `jd_too_sparse`.
- Calls `inspect_current_job()` to upsert.
- Updates the AgentRun to `succeeded` with sanitized result metadata.
- Returns `InspectJobOut`.

## Safety Invariants Preserved
- Cross-user access returns 404 (not 403) — dedup query scopes to `user_id`.
- No raw HTML persisted — JD dict is already sanitized by `sanitize_jd_result` at the bridge endpoint before reaching the service.
- `page_url_hash` (not raw URL) used for dedup — never persists the raw BOSS URL.
- Provenance in `jd_normalized._source` stores only safe identifiers (source_kind, page_url_hash, read_at, agent_run_id).
- The bridge channel remains in-memory and non-durable.
- One application_id per inspect call.
